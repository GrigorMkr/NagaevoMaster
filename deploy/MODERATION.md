# Модерация объявлений

Краткая инструкция: как публикует мастер, как проверяет администратор и что видит пользователь.

## Как это устроено

```
Мастер → «Добавить объявление» → статус pending
       → Админ в профиле → «Одобрить» / «Отклонить»
       → published → в каталоге и поиске
       → rejected → только в личном кабинете автора
```

Публичный каталог (`GET /api/listings`) отдаёт **только** объявления со статусом `published`.

---

## 1. Размещение объявления (мастер)

1. Войти на сайт (регистрация + подтверждение email).
2. Открыть **«Добавить объявление»** (`/add-listing`).
3. Пройти шаги:
   - **Категория** и **подкатегория** — обязательны, без них «Далее» неактивна.
   - **Описание** — заголовок, текст (минимум 10 символов), цена, телефон, адрес.
   - **Фото** — до 5 файлов, каждый до 2 МБ (необязательно).
   - **Предпросмотр** — карточка как в каталоге; кнопки «Категория», «Описание» и т.д. возвращают на нужный шаг.
   - **Публикация** — кнопка «Отправить на модерацию».
4. После отправки объявление получает статус **«На модерации»** (`pending`).
5. В **личном кабинете** (`/profile`) в блоке «Мои объявления» виден бейдж статуса.

Пока объявление на модерации, оно **не** отображается в каталоге и по ссылке для гостей недоступно.

## 2. Модерация (администратор / модератор)

### Учётная запись

В тестовой базе:

| Email | Пароль | Роль |
|-------|--------|------|
| `admin@nagaevomaster.ru` | `admin123` | admin |
| `demo@nagaevomaster.ru` | `master123` | user (обычный мастер) |

Роль `moderator` работает так же, как `admin`, для блока модерации.

### В интерфейсе

1. Войти как **admin@nagaevomaster.ru**.
2. Открыть **Профиль** — вверху появится блок **«Модерация объявлений»**.
3. Для каждого объявления в очереди:
   - **Одобрить** — статус `published`, объявление появляется в каталоге.
   - **Отклонить** — статус `rejected`, в каталоге не показывается; автор видит «Отклонено» в профиле.

Очередь пуста, если новых `pending` объявлений нет.

### API (для скриптов или Postman)

Нужен JWT в заголовке `Authorization: Bearer <token>` после `POST /api/auth/login`.

| Метод | URL | Описание |
|-------|-----|----------|
| `GET` | `/api/listings/moderation/pending` | Список на модерации |
| `PATCH` | `/api/listings/:id/status` | Тело: `{ "status": "published" }` или `"rejected"` |

Создание объявления: `POST /api/listings` (авторизованный пользователь) — сразу создаётся с `status: pending`.

Загрузка фото: `POST /api/uploads` (multipart, поле `file`, макс. 2 МБ).

## 3. Деплой изменений на сервер

После обновления кода в репозитории:

### API (VPS)

```bash
ssh nagaevomaster-vps
cd /var/www/nagaevomaster
git pull
bash scripts/vps/deploy-api.sh
```

Проверка: `https://api.nagaevomaster.ru/api/health`

### Фронтенд (REG.RU)

На локальной машине:

```bash
npm run build:hosting
npm run deploy:hosting
```

## 4. Контроль и типичные задачи

| Задача | Где смотреть |
|--------|----------------|
| Есть ли необработанные объявления? | Профиль админа → «Модерация объявлений» |
| Что отправил конкретный мастер? | Его профиль → «Мои объявления» + статусы |
| Жив ли API | `https://api.nagaevomaster.ru/api/health` |
| Логи API на VPS | `ssh nagaevomaster-vps` → `pm2 logs nagaevomaster-api` |
| Ошибки загрузки фото | Лимит 2 МБ; только `image/*` |

### Назначить модератора вручную (БД)

На VPS, если нужен второй модератор без роли admin:

```bash
ssh nagaevomaster-vps
cd /var/www/nagaevomaster/backend
npx prisma studio
```

Или SQL: обновить поле `role` у пользователя на `moderator` или `admin`.
